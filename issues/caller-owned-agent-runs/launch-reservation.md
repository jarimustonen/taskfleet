# Taskfleet launch reservation (Taskfleet slice)

`run session fence <full-run-id> --node n-0001 --checkout <exact-path> --output json` returns the persistent `launch_gate` and `writer` paths and their recorded `{dev,ino}` values. It checks the private run directory and ledger against the live caller-owned run. `state: foundation-only` and `launch_permission: false` are intentional: this query neither locks the gate nor permits Pi launch.

`run session reserve <full-run-id> --node n-0001 --generation 1 --pi-session-id <lowercase-uuid> --checkout <exact-path> --gate-fd <inherited-fd> --writer-fd <inherited-fd> --output json` records a durable **reserved, unbound** attempt before Pi starts. No `--session-path` is accepted: with `--session-id`, Pi chooses the filename `${timestamp}_${sessionId}.jsonl` at startup, and can defer writing even the header until an assistant message. The caller cannot know that timestamp before Start. Reservation records exact run/node/checkout/UUID/generation, not a guessed pathname, pre-created header, or proof of a child. The two FDs must be distinct inherited open descriptors (at least 3), with owner/mode/dev/ino matching the recorded persistent files; independent lock probes must find the gate and writer locked. The run event is checked against the ledger. An identical retry returns `idempotent_replay: true` without another event; a different generation or identity conflicts. `run show` and `node show` show `caller_agent.state: reserved` without `session_path`; `run wait` remains pending.

After Pi actually writes its header, discover the native path by the **reserved UUID** (not latest mtime), then `run session bind <id> --node n-0001 --generation 1 --pi-session-id <uuid> --session-path <actual-path> --checkout <exact-path> --output json`. Bind validates the native filename against its header timestamp and UUID, header cwd, safe path and inode, and matches the current reservation's UUID/generation. It fills the unknown path in the projection; a repeated bind revalidates the inode and returns idempotently. Replaced, stale or mismatched files fail closed. Only after `exec.Cmd.Start` succeeds can the host attest `run session update --state started` with the bound path/generation; `launch-failed` is for proved no-child failure and `control-uncertain` for a lost/unproven outcome, both without a path if still unbound. `exited` requires proved exit of the exact child. An unbound reservation cannot be marked started. Legacy already-bound sessions retain their lifecycle semantics. No Taskfleet command launches Pi or authorizes destructive settlement.

**Host integration is still required before any managed caller Pi launch.** The daemon, not the Taskfleet subprocess, must open and verify these two inodes from the trusted state root, hold the gate `LOCK_EX` and writer `LOCK_SH` on fresh open descriptions before invoking reserve, retain *both* across the CLI invocation and `exec.Cmd.Start`, and pass the shared writer FD to Pi via `ExtraFiles`. Do not unlock the gate between reserve and Start. The CLI validates inherited FDs and observes independently held locks but cannot attest who locked them or keep them held after it exits: its response is **never** an admission token. Any other entry point (including continuation) must use the same gate. There is not yet a settlement-intent transaction; existing caller-owned merge/cancel/salvage/discard remain refused. A lost reserve or Start reply must be reconciled against the durable current generation, the daemon's native Pi ownership lock and native history before any subsequent attempt. Do not pre-create Pi's JSONL to satisfy bind, assume `--session-id` opens an existing file, or generate a second UUID on timeout. Uncertainty preserves the checkout.

The advisory `flock` contract only covers cooperating host-launched writers; same-UID uncooperative writers are outside it. The daemon has not implemented this integration, so **the API is not usable as a safe Pi launch path yet**. Future settlement also needs a sticky intent and exclusive writer lease through merge and teardown; a lifecycle exit does not substitute for that fence.
