# Caller-owned Pi session binding (implemented slice)

`taskfleet run session bind <full-run-id> --node n-0001 --pi-session-id <lowercase-uuid> --session-path <absolute-jsonl-path> --checkout <absolute-recorded-checkout> --output json` binds once. `node show <run-id> n-0001 --output json` reads `data.caller_pi_session`; `run show <run-id> --output json` also exposes `data.caller_pi_session` for a single-node run. Historic nodes have `null` on node show and no binding on run show. Neither field is worker `evidence`.

The bind response uses the standard `{schema_version:1,data:{run_id,node_id,caller_pi_session:{pi_session_id,session_path,original_cwd,file_dev,file_ino},idempotent_replay}}` envelope. The node projection and `caller.pi.session_bound` event contain the same immutable identity. An identical retry revalidates the native file identity (device and inode; append growth is allowed) and emits no second event. Conflicting identity or a missing/replaced checkout returns `pi_session_conflict` (exit 1); malformed/foreign/changed native source returns `invalid_pi_session` (exit 1). The exact recorded checkout and full run/node IDs are mandatory. Bind checks the first native `type=session`, `version=3`, `id`, and `cwd` line (max 16 KiB) in a regular same-UID file of at most 512 MiB beneath the private `HOME/.pi/agent/sessions` directory. It opens path components without following symlinks and checks metadata around the header read. This is an association with a path, not permission to read arbitrary files or evidence of who is writing Pi history.

Reading the projection after teardown does **not** reopen the Pi path or require the checkout to exist. Native history remains Pi's responsibility. The host still needs a safe post-teardown history-read route keyed by the bound identity and a durable native-file retention policy; its current workspace-discovery route requires an extant checkout. This slice does not launch Pi, archive history, attest daemon identity, grant writer-quiescence/teardown authority, or enable caller-owned settlement (the writer fence remains unavailable). Same UID alone cannot authenticate the daemon process.

`--dry-run` explicitly returns `dry_run_unsupported`: an open native file and its writer cannot be reserved by a read-only plan. No workmux call is made in binding or inspection. Fixture tests use disposable homes and synthetic JSONL only; no personal Pi process is launched.
