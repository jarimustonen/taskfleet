# Release bump snapshot repair

## Diagnosis and choice

`29a4cb09` (`release: v0.17.0`) changes all five version-bearing snapshots from 0.16.0 to 0.17.0. Its hook already uses `INSTA_UPDATE=always` and the same five-file allowlist; the last hook change was `22f59555`, adding the two skill-list snapshots. Thus 0.17.0 did not succeed by ignoring the version or by having a different hook: its regenerated bytes are in the release commit. Git does not establish the execution environment used then.

The failed 0.17.1 archive shows the test compiling in `/j/src`, against stale snapshots, and failing rather than updating. Its profile specifies `host-cargo-test`, with no output artifacts. The host's ambient Cargo dispatches tests to that offload system. This is unsuitable for a hook that must preserve `INSTA_UPDATE` and mutate its own checkout.

Retain literal versions, not redaction. They verify the release version across the CLI and bundled skill catalog; the existing deterministic regeneration and non-snapshot side-effect guards remain useful. The hook now resolves stable Cargo through rustup and prepends the real toolchain directory locally, just as the exact-commit gate does. It uses release-mode tests, matching repository policy.

## Regression coverage and focused self-review

- The hook fixture puts a failing ambient Cargo wrapper first on PATH. A lookup-only rustup stub selects a distinct local toolchain. This would fail with the old hook.
- Existing cases still cover partial regeneration, missing/malformed snapshots, unchanged snapshots, `.snap.new`, tracked/untracked side effects, and Cargo failure.
- The full protocol fixture deliberately strips PATH and isolates HOME. It now provides a strict lookup-only rustup stub returning its already-pinned stable Cargo; no real rustup proxy can install or select tools in the sandbox.
- Reviewed shell syntax, staged diffs, fail-closed command handling, and the five-file allowlist. No CLI shape, snapshot baseline, installed taskfleet binary, or installed taskfleet skill changed.

## Evidence

- `simulated-bump.log`: disposable clone of the fix, workspace/core pin/lock bumped to 0.17.1. The real hook regenerated all five snapshots. Release-mode nextest: **1278 passed, 1 skipped**. Both core doctests passed. A byte comparison proved all eight changed files differ only by `0.17.0` → `0.17.1`.
- `gate.log`: initial full gate passed Rust checks and shell fixtures until the current-engine protocol fixture exposed its missing rustup lookup. Corrected the fixture rather than weakening isolation. The final full rerun is recorded in `gate-final.log`.
- `resume-help.txt`: installed engine resume help; no source-retargeting option. Engine durable plans execute the sealed checkout, so resume of the old run cannot incorporate this fix.

The disposable clone is retained beside the logs. It is not a release cut; no tag, registry publication, tap edit, installed binary replacement, or taskfleet skill install was performed.
